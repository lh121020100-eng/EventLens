# EventLens — 投资事件情报与证据时间线

> 问一句，知全貌；循证据，看演化。

**状态：可运行 Web MVP（静态独立运行 + 可选服务端大模型抽取）**

EventLens 面向个人投资者和投研分析人员，围绕**同一持续演化的投资事件**组织公司公告、新闻和研究观点，展示可追溯的主张核验、时间线、结论版本和关注通知。原型以双成药业（002693）收购奥拉股份的历史交易为唯一覆盖的真实主案例，避免伪装成全市场实时系统。

## 2. 已实现的用户操作

| 功能 | 实际行为 |
|---|---|
| AI 投研助手入口 | 识别主案例相关关键词，返回有来源的事件摘要；其他事件明确告知不支持 |
| 单页事件详情 | 顶部结论和关联标的 + 下方 50:50 纵向时间线与节点详情 |
| 节点证据详情 | 切换主张、查看简洁核验结论、原文片段、四类时间及原始公告链接 |
| 分类与评分 | 事实性主张/观点/推测/传闻；权威性 40%、直接性 25%、独立性 15%、时间 15%、完整性 5% |
| 同一事件识别 | 主体、交易对象、事项连续性；明确合并 / 待审核 / 不属于同一事件 |
| 事件版本 | V1 筹划中 → V2 预案已披露 → V3 已终止；新闻重复不建新版本 |
| 历史回放 | 清空后逐份输入真实历史材料、重新计算版本和变化日志 |
| 新证据导入 | 粘贴原文、日期及链接；执行真实的匹配、抽取、评分和日志入库 |
| 用户关注/站内通知 | 关注后，回放中确认的状态变化会产生站内通知 |
| 异常与合规 | 非本事件不强合并、重复正文不重复入库、手动冒充官方来源不得覆盖已核实结论 |

当前数据保存在浏览器 `localStorage`（隐私模式等受限环境中只保存当前页面会话）；跨设备同步、真实后台监控未实现。

## 3. 架构与 AI 角色

```text
浏览器 / src/app.js
   │
   ├── 事件摘要与详情 · 单页 UI
   ├── 文档导入、历史回放、关注通知
   │
   ▼
src/engine.js                         可选：netlify/functions/analyze.mjs
   ├── Step1 结构化文档记录                └── OPENAI_API_KEY 配置后服务端 LLM 主张抽取
   ├── Step2 主体+标的+交易连续性检查      │
   ├── Step3 原子主张提取 / 类型标签  ◄────┘ 只有服务器实际返回成功才标记 LLM 模式
   ├── Step4 证据质量五维内部评分 / 去重
   ├── Step5 状态机 + 重要版本快照
   └── Step6 结构化展示 + 站内通知
        │
        └── localStorage（MVP）
```

**AI 的真实作用与边界**：
- 若托管平台设置了 `OPENAI_API_KEY`，后端使用模型对粘贴原文抽取结构化 Claim；模型不能直接写入已验证的事实状态，也不能自称验证了手动粘贴内容。
- 未设置 API key 时，使用**可测试的规则式提取**。这属于确定性 NLP / 规则引擎，**并非大模型推理**，界面清晰显示「规则核验模式」。
- 不论 AI/规则输出，原文 `quote` 必须能在导入文本中找到，否则丢弃。
- 评分仅用于引擎内部的证据关系辅助评估，**前端不展示数值分数**；用户只看到结论、必要的解释和原始证据链接。评分不是事实为真的概率。
- 权威官方披露本身也不能证明公告以外的预测；公司是否明确披露终止决定，与未来股价涨跌是不同的命题。

### 五维评分

`证据分 = 0.4×权威性 + 0.25×直接性 + 0.15×独立性 + 0.15×时间相关性 + 0.05×完整性`

先核对是否针对同一实体、事项与时间范围，再比较具体主张的证据；重复转载不得重复累加。五个分项为可解释启发式初始参数，**尚未经金融标注集校准**。

## 4. 运行与上线

### 本地启动（无需安装前端依赖）

要求 Python 3，Node.js 20+ 用于测试。

```bash
cd EventLens_MVP
python3 -m http.server 4173
# 浏览器访问 http://localhost:4173
```

```bash
npm test
```

### Netlify 手动部署（零配置规则模式）

1. 解压 `EventLens_MVP_netlify_static.zip`。
2. 打开 https://app.netlify.com/drop 。
3. 拖入解压得到的 `index.html` 与 `src/` 所在的整个目录（不要只拖 `index.html`）。
4. Netlify 给出实际 `https://<your-site>.netlify.app` 公网 URL，浏览器打开核对事件时间线。
5. 此方式仅部署静态前端，规则引擎及浏览器持久化可运行，**不会启用服务端 LLM Function**。

### Netlify Git 仓库部署（支持 LLM）

1. 在 GitHub 新建仓库，提交本项目的完整源代码。
2. 在 Netlify 选择 `Add new project → Import an existing project → GitHub`，选择该仓库。
3. 仓库根目录保留 `netlify.toml`，publish 设为 `.`，functions 为 `netlify/functions`。
4. 在 Netlify 环境变量中设置 `OPENAI_API_KEY`，可选 `OPENAI_MODEL=gpt-4.1-mini`。
5. **不得**把 API key 提交到仓库、写在前端 JS 或交给浏览器。
6. 新增材料后可在页面顶部观察真正的 LLM / 规则模式标识，若服务端失败将自动退回规则模式。

**部署说明**：当前会话没有授权连接 GitHub/Netlify/Vercel，因此没有对外声明已经发布在线 URL；交付的是经过本地测试、可部署的完整项目。

## 6. 数据对象与时间

- `Event`：业务事项身份、主体/交易标的。
- `Document`：来源、原文录入片段、披露时间、抓取时间、更新时间。
- `Claim`：具体主张、信息类型、原文位置（文本片段）、主题。
- `Assessment`：主张级五维评分及证据关系判断说明。
- `EventVersion`：事件状态快照、关联证据、触发原因、前置版本。
- `Change/Notification`：版本变化及关注提醒。
- `AuditLog/PendingMatch`：完整处理路径、错误和待审核事项。

时间规则：默认按披露时间组织时间线；事项发生时间允许未知；浏览器实际导入时产生 `fetchedAt`、`updatedAt`，**不会伪造历史采集时间**。

## 7. 已知限制与未做事项

**核心限度（请务必在笔试答辩中如实说明）**

- 当前是**单事件垂直切片**，并非全市场多事件生产平台。
- 默认规则抽取有限，不能替代金融领域的大规模模型评估；生产环境应增加结构化校验、抽取回归测试和人工复核。
- 手动导入的文本不能自动验证其网址是否与内容一致，因此只保存为“待核实”并限制其权威性；不会因此自动推翻已经核对的公司公告。
- 同义主张全量聚合、复杂跨来源时间范围的蕴含/矛盾推理仍为简化版；目前提供基本分组和冲突预警，不能宣称已具备完全自动的金融事实核验能力。
- 由于没有后端账户系统，`localStorage` 的关注、通知和日志无法跨浏览器共享。
- 无全市场 7×24 实时采集；无自动交易、推送短信、行情数据与收益预测。
- 如果部署为纯静态站点，即使用户填写 HTTPS 原文链接，也不进行远程 PDF 抓取或自动 OCR；用户需要粘贴正文。

## 9. 安全与合规

- 所有人工输入文本均在渲染时 HTML 转义，外部来源仅接受 HTTPS 链接且以新标签页打开。
- 服务端密钥只作为环境变量读取；模型返回的 `quote` 必须确实出现于原文中。
- 用户来源自称“官方”，不代表已完成来源身份认证。
- 提供出处和不确定性说明，不将研究观点或预测直接升格为已证实的客观事实。
- 不建议依赖该产品单独作出股票投资决策。
